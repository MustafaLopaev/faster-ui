# Data Model: Quality Automation Layer

The entities this feature introduces. None is a runtime type — these are the shapes of the *evidence* the automation produces, stores and compares. Where an entity is persisted in the repository, its path and format are stated, because a committed artifact is a contract with every future reader.

## 1. Check

One automated verification. Fifteen instances (the spec's thirteen automations, with the visual check split into its comparison and judgment halves, and the surface record separated from its classifier).

| Field | Type | Notes |
| ----- | ---- | ----- |
| `id` | `string` | Stable identifier, also the CI job id — **renaming is a breaking change** to required-check configuration, exactly as 003 established for its seven gates |
| `group` | `'A' \| 'B' \| 'C'` | Deterministic / model-driven on PRs / off the PR path |
| `trigger` | `'push' \| 'pull_request' \| 'workflow_run' \| 'schedule' \| 'local'` | |
| `pathFilter` | `string[]` | Empty means always. A docs-only change must match nothing (FR-005) |
| `needsCredential` | `boolean` | When true, the job skips green if the secret is absent (FR-019) |
| `blocking` | `'required' \| 'advisory' \| 'never'` | `never` is structural for review jobs (FR-017), not a policy setting |
| `localCommand` | `string` | The npm script a contributor runs to get the identical result (FR-001) |

**Invariant**: `needsCredential && blocking === 'required'` is forbidden. A check that cannot run for a fork must never be able to block one. This is enforceable by inspection of the inventory table and is the single rule that keeps the pipeline usable without the secret.

**Invariant**: every `Check` has a non-empty `localCommand`. A check reachable only through CI violates FR-001.

## 2. Verdict

What a check returns. Deterministic and model-driven checks return the same shape so the triage agent (C2) and the audit (C5) can read both without branching.

| Field | Type | Notes |
| ----- | ---- | ----- |
| `check` | `Check['id']` | |
| `status` | `'pass' \| 'fail' \| 'skipped'` | `skipped` is a success outcome, not a soft failure |
| `skipReason` | `'no-credential' \| 'fork' \| 'path-filter' \| null` | Non-null only when `status === 'skipped'`; makes an absent check legible rather than mysterious |
| `findings` | `Finding[]` | Empty on pass |
| `usage` | `{ inputTokens, outputTokens, cacheReadTokens } \| null` | Model-driven only. `cacheReadTokens === 0` across runs means the cached prefix is silently not working (FR-037) |

## 3. Finding

One reported problem. Every finding must be locatable, or it cannot be acted on.

| Field | Type | Notes |
| ----- | ---- | ----- |
| `file` | `string` | Repository-relative |
| `line` | `number \| null` | Null only where the subject has no line (a rendered cell, a packaging declaration) |
| `rule` | `string` | Principle number, axe rule id, or check-specific code |
| `severity` | `'error' \| 'warning'` | |
| `message` | `string` | States the defect, never merely that something differed |
| `evidence` | `string` | The quoted source, measured ratio, or cell id that substantiates it (FR-015) |

**Invariant**: `evidence` is non-empty. A finding a reviewer cannot check is a finding they will learn to ignore.

## 4. Public Surface Record

**Persisted**: `etc/faster-ui.api.md`, generated by api-extractor from `dist/index.d.ts`.

| Property | Value |
| -------- | ----- |
| Format | api-extractor's canonical report — declarations in a stable order, so the git diff is signal not bundler noise (research R-7) |
| Verified size | 2,478 bytes covering all 12 exports *(verified by trial run)* |
| Update rule | Regenerated by `npm run api:report`; CI runs the same tool without `--local` and fails if the committed file differs |
| Authority | This file, not `dist/index.d.ts`, is the reviewable public contract |

**Known open finding, carried into the record from the trial run**: `ae-forgotten-export` — `ButtonBaseProps` is extended by both `TextButtonProps` and `IconOnlyButtonProps` but is not exported from `src/index.ts` *(verified)*. A consumer cannot name the base type. This is a genuine pre-existing defect in the public surface. Fixing it changes the public API, which this feature's Out of Scope forbids, so the record is committed **with the warning visible** and the fix is a separate change. Suppressing the warning to get a clean first commit would discard the first real thing this gate found.

**Escalated during implementation** *(verified both ways)*: the leak is not only a naming gap, it is a **blind spot in this gate**. An optional prop added to the exported `TextButtonProps` fails `api:check`; the same prop added to the unexported `ButtonBaseProps` **passes**. `size` and `loading` live on that base type, so they are part of every Button's public API and outside the recorded contract. The record is committed with the warning written *into* it (`addToApiReportFile: true`), so it is re-read on every surface change. Full detail: [findings.md](./findings.md#f-1--buttonbaseprops-is-not-exported-and-the-surface-record-is-blind-to-it).

## 5. Semver Classification

Derived by comparing two revisions of the Public Surface Record.

| Field | Type | Notes |
| ----- | ---- | ----- |
| `required` | `'major' \| 'minor' \| 'patch'` | |
| `rationale` | `string` | Which declaration forced it |
| `claimed` | `'major' \| 'minor' \| 'patch' \| null` | Inferred from the `## [Unreleased]` section; null when absent |

**Rule set** (the classifier's rubric, stated here because it is a contract, not a prompt detail):

| Surface change | Increment |
| -------------- | --------- |
| Export removed or renamed | major |
| Required prop added | major |
| Union member removed from a prop type | major |
| Prop type narrowed | major |
| **Union member added to a discriminated union** | **major** — new members change exhaustiveness checking in consumer code |
| Optional prop added | minor |
| Union member added to a non-discriminated value union | minor |
| Export added | minor |
| Documentation-only change | patch |

The bolded row is the one a human reviewer most often gets wrong, and is why this classification is worth automating at all.

## 6. Visual Cell

The unit of visual evidence. Its identity **is** its filename — no sidecar index to fall out of sync.

| Field | Type | Notes |
| ----- | ---- | ----- |
| `storyId` | `string` | From `storybook-static/index.json` |
| `theme` | `'light' \| 'dark'` | |
| `palette` | `'figma' \| 'aa'` | |
| `viewport` | `360 \| 768 \| 1280` | |
| `scale` | `100 \| 200` | Text scaling percentage |
| `direction` | `'ltr' \| 'rtl'` | |
| `motion` | `'default' \| 'reduced'` | |
| `content` | `'story' \| 'adversarial'` | Which fixture set supplied the props |

**Filename**: `{storyId}__{theme}-{palette}-{viewport}-{scale}-{direction}-{motion}-{content}.png` under `visual/baselines/`.

**Population** is the layered set from research R-4 — **233 cells**, not the 4,416-cell cross-product:

| Layer | Cells |
| ----- | ----- |
| Base grid (23 stories × 2 themes × 3 viewports) | 138 |
| Palette sweep (23 × 2 themes @ 1280) | 46 |
| Scaling sweep (23 @ 360, light, 200%) | 23 |
| Direction sweep (23 @ 768, light, rtl) | 23 |
| Motion sweep (animating stories only) | 3 |
| **Total** | **233 ≈ 7.7 MB** |

**Excluded**: `foundations-design-tokens--all-tokens`. It is a documentation page, not a component, and measures **1.4 MB per capture** — a 42× outlier that would be roughly 40% of the entire set *(verified by measurement)*. Recorded here so a future reader does not "restore" it.

**Platform validity**: baselines are captured on `ubuntu-latest` and are valid only there (research R-1). A locally captured baseline will differ on font rasterisation alone.

## 7. Visual Comparison Result

| Field | Type | Notes |
| ----- | ---- | ----- |
| `cell` | `VisualCell` | |
| `state` | `'unchanged' \| 'changed' \| 'new' \| 'orphaned'` | `orphaned` = a baseline whose story no longer exists; must be reported, not silently kept |
| `diffRatio` | `number` | Fraction of differing pixels |
| `judged` | `boolean` | True only for `changed` and `new` (FR-026) |

**Threshold**: a cell is `changed` when `diffRatio > 0.001` at a per-pixel threshold of `0.1` (research R-3). Only `changed` and `new` proceed to judgment — this ordering is what makes the check affordable, and reversing it costs roughly 12× for information the comparison already settled.

## 8. Jury Verdict

Returned as schema-validated JSON via the action's `structured_output` (research R-11), so it cannot come back malformed.

| Field | Type | Notes |
| ----- | ---- | ----- |
| `cell` | `string` | The filename |
| `verdict` | `'PASS' \| 'WARN' \| 'FAIL'` | |
| `defect` | `string` | Required and non-empty when not `PASS`. Must name the defect — "label clipped at the right edge", not "differs from baseline" (FR-027) |
| `confidence` | `'high' \| 'low'` | A `low` marks the cell for human attention rather than being silently trusted |

## 9. Consumer Fixture

| Field | Type | Notes |
| ----- | ---- | ----- |
| `id` | `'vite-app' \| 'next-app' \| 'ts-resolution'` | |
| `installs` | `string` | The packed tarball path — never a workspace link, which would resolve through symlinks and miss a broken `exports` map (research R-8) |
| `asserts` | `string[]` | vite: build succeeds · next: build + zero console errors/warnings on load · ts-resolution: typechecks under `bundler`, `node16`, `nodenext` |

**Constraint**: fixtures carry their own manifests and are never part of the root install. Adding them there would put a framework in the library's own dependency graph, which FR-004 forbids.

**Note**: the Next.js fixture must import `styles.css` explicitly, because `dist/index.js` contains **no CSS import** *(verified)*. This makes the fixture exercise a documented consumer step rather than a side effect.

## 10. Adversarial Content Set

**Persisted**: `visual/fixtures/adversarial.ts`. Generated once, then **frozen** — regenerating it per run would make the matrix irreproducible (FR-028).

| Case | Purpose |
| ---- | ------- |
| 200-character label | Overflow, wrapping, `min-width` interaction |
| Arabic string | Right-to-left layout, directional adornment order |
| Emoji and combining marks | Line-height and baseline stability |
| Zero-width joiner sequence | Grapheme handling in truncation |
| 500-row modal body | Scroll containment, header/footer stickiness |
| Empty string / single character | The opposite boundary of the long label |

## 11. Accessibility Result

| Field | Type | Notes |
| ----- | ---- | ----- |
| `component`, `variant`, `theme`, `palette` | `string` | The cell under test |
| `rules` | `string[]` | The active axe rule set |
| `violations` | `Finding[]` | Must be empty (FR-011) |

**Rule scoping — the design's load-bearing decision** (research R-6):

| Palette | `color-contrast` | Why |
| ------- | ---------------- | --- |
| `figma` (default) | **disabled** | The palette fails AA by design — 27 deviations pinned in `src/tokens/tokens.test.ts` *(verified)*, including the primary Button label at 2.11:1. That test is a **stricter** authority: it is two-sided, so a value can neither worsen nor silently improve without the record changing |
| `aa` (overlay) | **enabled** | Reaching AA is the overlay's entire promise; this is where it is proven |

Every other axe rule runs on both palettes.

## 12. Drift Report

**Not persisted in the repository** — emitted as an issue by the local `/design-drift` skill (research R-12).

| Field | Type | Notes |
| ----- | ---- | ----- |
| `token` | `string` | The `--fui-*` name |
| `figmaValue`, `codeValue` | `string` | |
| `status` | `'drift' \| 'recorded-deviation' \| 'unreachable'` | |

**Suppression source**: `specs/001-foundation-tooling/figma-extraction.md` and `specs/002-core-components/figma-extraction.md`. Deliberate deviations — `radius-surface` at 4px, the AA overlay values — are `recorded-deviation` and never reported as drift (FR-031).

**`unreachable` is a required state**, not an error path. When the connector is unavailable the report says so; an all-clear it did not establish is worse than no report at all (FR-032).
